# agent-forge — спецификация (итог grilling, 2026-10-01)

Исходная идея: скилл, который по запросу пользователя создаёт ИИ-агентную систему под любую задачу, начиная с блиц-опроса (grilling), с описанием лучших практик крупных компаний, чистым оптимизированным кодом и современным UI с анимациями.

Принципы написания скиллов: предсказуемость; проверяемый критерий готовности у каждого шага; ведущие слова; тест на no-op; позитивные формулировки; один источник правды; детерминированное — в скрипты; скрипт отвечает понятной `ERROR:`; совместное размещение; деление по вызову/последовательности; неотменяемое — в хук; обрезка осадка.

| 21 | Память | Один Postgres: рабочая (сообщения + компактификация), знания (`pgvector` + FTS hybrid, ответ со ссылкой на источник), факты (инструмент `remember`, источник+дата, удаление); ненужное не создаётся |
| 22 | Трейсы | OTel → своя таблица в Postgres, UI читает оттуда; экспортёр (Langfuse/OTel) одной переменной; по умолчанию только метаданные |
| 23 | Инструменты | Единый реестр, нативные AI SDK и MCP по одному контракту: схема, класс риска `read/write/destructive`, обоснование, понятная ошибка, таймаут/ретраи; `write/destructive` — подтверждение; MCP по allowlist; `check-tools` |
| 24 | Промпты | `prompts/*.md` с frontmatter, типизированный лоадер, хэш в трейсе и eval-прогоне, изменение промпта = изменение кода (evals в CI), шаблон системного промпта |
| 25 | Guardrails | Слои: структура (недоверенный контент как данные, least privilege, HITL) → детерминированные проверки (лимиты, маскирование секретов/PII, валидация аргументов) → лимиты исполнения (шаги/токены/стоимость) → LLM-классификатор только по рискам из опроса; каждый слой покрыт adversarial-evals |
| 26 | Авторизация | Не строим — отдельный продукт |
| 27 | Идентичность | Шов `getIdentity(request) → { userId, roles }`; адаптеры `local` (по умолчанию, только 127.0.0.1) и `trusted-header`; память/факты/трейсы/лимиты привязаны к `userId`; старт отказывает публичному bind с `local` |
| 28 | Запуски | Durable run: таблица `runs` (`queued/running/awaiting_approval/done/failed/cancelled`), очередь на Postgres, процесс `worker`; чат/крон/вебхук ставят в очередь; стрим возобновляется, отмена; идемпотентность вебхуков; Vercel + фон = ошибка `validate-spec` |
| 29 | Качество кода | `check-code`: strict TS без `any`; линт/формат; `knip`; TDD инструментов (100 % реестра и шва); зависимости с причиной, `npm audit`; бюджет бандла и время до первого токена; трассировка модулей к спеке (Simplicity First). Плюс: комментарии «почему»; TSDoc на экспортах + `ARCHITECTURE.md`, сверяемый скриптом; `O(…)` и property-based тесты (`fast-check`) для нетривиальных алгоритмов; нет N+1 (счётчик запросов); бенчмарки hot path (регрессия >20 % = red); индексы под частые запросы через `EXPLAIN` |
| 30 | DoD v1 | 3 эталона проходят все гейты насквозь; провокационные pressure-кейсы удержаны; `lint-skills` green; установка проверена в Claude Code (плагин) и Hermes (`npx skills add`); README EN; каждый `SKILL.md` ≤ 500 строк |
| 31 | Объём evals | На опросе 5–10 реальных кейсов; в фазе `evals` скрипт расширяет до ~20 (вариации + adversarial из gap sweep), пользователь подтверждает «да/нет» на кейс; детерминированный split на dev и holdout, holdout — только перед релизом |

## Решения по итогам исследования (2026-10-01, см. `.research/SUMMARY.md`)

- UI-шаблоны на базе **AI Elements** (Vercel, Apache-2.0, исходники копируются) + свои агентские паттерны.
- Pressure testing набора — через **`claude plugin eval`** (кейсы, грейдеры, моки MCP, baseline без плагина, `--max-cost-usd`).
- Установка в Hermes — `hermes skills install` / repo-local `.agents/skills` (у `npx skills add` нет цели Hermes).
- Стек уточнён: AI SDK 7 (`ToolLoopAgent`, `isStepCount`, `toolApproval`, `telemetry`), `@ai-sdk/mcp`, pg-boss 12 (named import), Drizzle 0.45, Next.js 16, Tailwind 4, motion 13, Biome, pnpm, vitest 5.
- Скрипты и шаблоны живут внутри скилла `agent-forge` (ядро); фазовые скиллы ссылаются на них относительным путём — так набор работает и как плагин, и при поштучной установке скиллов.

## Порядок работ

1. **Исследование** — 6 репозиториев скиллов + andrej-karpathy-skills; первоисточники практик (Anthropic, OpenAI, Google, Microsoft, AWS, Vercel); актуальные версии стека. Результат: правила с источниками и датами + решение о vendor.
2. **Скелет** — плагин, маршрутизатор, `state.json`, `phase-gate`, 5 фаз минимально; эталон «агент поддержки» насквозь.
3. **Наращивание** — grill → architect → build → evals → ui; после каждой `lint-skills` + pressure test.
4. **Релиз** — README, marketplace, `sync-upstream`.
