# Practices — grill

Format and upkeep: [practices index](../../agent-forge/references/practices-index.md).

- **GR-01** Decide whether the task even needs an agent: check if a single LLM call, a retrieval-augmented call, or a deterministic workflow already satisfies the requirement before committing to an agentic loop. — Source: [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) (Anthropic) — Check: interview transcript/spec must record why the chosen complexity tier was picked over every simpler alternative (single call, RAG, workflow) — Verified: 2026-10-01
- **GR-02** Classify every candidate tool/action by risk (low/medium/high) based on reversibility, required permissions, and financial impact before architecture starts. — Source: [A practical guide to building agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf) (OpenAI) — Check: grill output contains a tool-risk table with a risk tier per planned tool, non-empty for any workload with write/delete/pay tools — Verified: 2026-10-01
- **GR-03** Capture an explicit exit/stop condition for every planned run (max turns, specific structured output, error threshold) during the interview, not after building. — Source: [A practical guide to building agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf) (OpenAI) — Check: architecture doc lists a concrete stop condition (step cap, schema match, timeout) for every agent/workflow node — Verified: 2026-10-01
- **GR-04** Ask explicitly which actions require human approval (irreversible, financial, destructive) and record them as a separate, named list before architecture. — Source: [A practical guide to building agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf) (OpenAI) — Check: grill output has a dedicated "approval-required actions" list; any write/delete/pay tool from GR-02 must appear on it or carry an explicit justification for not requiring approval — Verified: 2026-10-01
- **GR-05** Enumerate every untrusted/external data source the agent will ingest (web pages, emails, uploaded files, tool outputs from third parties) — each is a prompt-injection attack surface. — Source: [Mitigating the risk of prompt injections in browser use](https://www.anthropic.com/news/prompt-injection-defenses) (Anthropic) — Check: spec contains an explicit "untrusted data sources" list that is cross-checked against BU-09's injection-point implementation — Verified: 2026-10-01
- **GR-06** Do not default to multi-agent: require a specific justification (parallelizable breadth-first subtasks, context exceeding one window, tool-count overload) before the architecture phase is allowed to introduce more than one agent. — Source: [How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) (Anthropic) / [A practical guide to building agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf) (OpenAI) — Check: any multi-agent design in the output spec cites one of the named justifications explicitly, not "for modularity" alone — Verified: 2026-10-01
- **GR-07** Fix a numeric cost/latency budget (max tokens per run, target p95 latency) during the interview, since agentic systems trade both for accuracy. — Source: [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) (Anthropic) — Check: spec has required numeric fields `max_tokens_per_run` and `target_latency_ms` — Verified: 2026-10-01
- **GR-08** Confirm the task has an available "ground truth" signal the agent can check against mid-run (tool result, test execution, structured API response); flag tasks without any such signal as poor agent fits. — Source: [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) (Anthropic) — Check: spec names at least one verifiable feedback source per planned agentic task; tasks with none are routed to a simpler workflow pattern instead — Verified: 2026-10-01
- **GR-09** Pin the baseline model to the strongest available model during interview/architecture; defer any cheaper-model substitution decision until after an eval suite exists. — Source: [A practical guide to building agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf) (OpenAI) — Check: spec names an explicit baseline model and contains no model-downgrade decision prior to the evals phase — Verified: 2026-10-01
